## #350 — the width the record already held (`8781ea50`)

`concurrency` was refused on both engines and both refusals were correct about
what they refuse. The ollama one ends by naming where the answer is —
*"obtainable only with access to the serving host (`tools/bench/serving/`)"* —
and the `host` block written beside it **in the same file** is produced by that
module, with that access, and already carried the number. `fingerprint.py`
had even classified `n_parallel` and `total_slots` as semantic, under its own
comment *"batching and caching — decide whether a re-run reproduces at all"*.

**The fix is one shape different from what the issue specified, and the
difference is the point.** Box 1 said "populate `concurrency` from the host
block". It must not be. This file has exactly one organising axis — `native` is
what the endpoint said, `host` is what the machine said — and a host reading
under the `native` label destroys it. So the refusals stay **byte-identical**
and the answer goes to a third source, `resolved`: what the two together settle.
The issue's DoD was written before the module was read closely enough, and it
is corrected there rather than quietly satisfied.

`pin.width` normalises the read across engines; the vLLM half is
`launched_width`, **which already existed and was wired to nothing on this
path**. Two host sources that disagree are refused rather than resolved.

And the dispatch side, which no probe can recover: a server cannot see how many
requests a client chose to keep in flight, so if the call site does not say it,
nothing does. Both runners pass it now, computed off the endpoint the runner was
built from.

**What the pair licenses is written in the module**, because it is easy to
over-read: `served_width` 1 licenses "the batch was 1"; `dispatch_max_parallel`
1 does not, because it bounds the batch only if this run was the sole client.

## #349 — four states, one value (`68142ad9`)

"There is no hostname", "the address is loopback", "the name did not resolve"
and "the probe raised" all arrived as `{}`. Three are ordinary absences and the
fourth is a **broken reading**, so the one state a reader could not act on was
indistinguishable from the three they could — the collapse this harness refuses
twice on purpose (`gpu_idle`'s "None is NOT idle", the compute-apps `&&`
sentinel) and committed here anyway.

**One claim in my own issue was wrong and is corrected at source.** I had listed
a hosted endpoint as a fourth `{}`. It is not: `contract.ssh` returns `None`
rather than raising, so a hosted endpoint whose name resolves goes past all
three early returns and produces a **fuller** record than an empty one.
Measured against the module, not reasoned. The defect stands; one of its four
examples did not, and a check now pins the corrected claim.

## #348 — the scored path reads the card (`47e7180d`)

Every reading that describes the machine already existed as a declared constant
and the only production caller was the serving **calibration** runner. The
instrument that ships the trunk's numbers recorded `latency_s` and nothing about
the silicon that produced it.

The probe composes the constants that already declare each part — card state,
compute apps, load average — into one ssh. **Semicolons between the sections and
`&&` inside them**: `;` so one failing reading does not take the others down,
`&&` so a query that printed nothing cannot have its sentinel printed anyway.
Sections are sliced by sentinel rather than by the shape of a line, because
handing the whole reading to each parser works today only by a guard doing a
second job by luck.

**Per task, not on a timer.** A task is the unit rows group by; the reading
costs one ssh (p50 0.956 s, measured) against a task that takes minutes.

**The recorder must not be able to damage the run it records.** An ssh to a host
that has gone away costs its 15 s ConnectTimeout every time, so the sampler
gives up after three **consecutive** failures and says so on its last row.
Consecutive, not cumulative: one dropped packet is not a dead host.

Live-verified on both rigs before the checks were written — srv1 49 C / 14.98 W
/ 300 MHz, srv2 42 C / 21.15 W / 210 MHz, `placements: []` on an idle card, and
an unreachable host returning `placements: null` rather than `[]`. **The
sentinel's distinction confirmed on the wire rather than argued for.**
