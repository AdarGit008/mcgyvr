### `81f22bf6` — the trap stops the phases that have not started

`pkill -P $CHILD` and `kill $CHILD` are two commands. The instant `pkill` signals
the phase in flight, `wait` returns and the subshell forks the **next** phase
before `kill` arrives; that phase is reparented to init and never signalled. So
`cleanup` releases all four pairs while an orphaned survey re-claims the cards and
runs on unsupervised — writing rows `--resume` would afterwards treat as done.

Measured on stand-ins: **4 of 20** SIGTERM trials here, 17 of 30 in a run whose
kill landed later in the phase. With the sentinel, **0 of 20**. Normal completion
still runs all three phases and releases exactly once; a phase exiting non-zero
still does not cancel the ones behind it.

The test pins the ORDER, not the presence — a `touch` after the kills would pass a
substring test and close nothing. Negative control confirms it fails when swapped.

### Recorded because it changes what the operator types

**`kill -INT` on the driver does nothing.** The driver is started as an
asynchronous command with job control off, and POSIX requires the shell to set
INT and QUIT to `SIG_IGN` in such a child; a trap cannot re-enable a signal
ignored on entry. Read off a live driver: `SigIgn` = HUP+INT+QUIT, `SigCgt` =
TERM+CHLD only. Verified twice — `kill -INT` left it alive with no release;
`kill -TERM` released cleanly. **Stop the driver with a plain `kill <pid>`.**
