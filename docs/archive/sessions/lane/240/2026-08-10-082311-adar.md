## Did

Retired the five declared instrument sets and released them for training,
retired HumanEval+ and barred it from training permanently, and split the guard
#230 built into the two flags that were hiding inside it. ADR-0020 records the
decision and its three rejected alternatives.

**The declaration carries `retired` and `trainable`, and they cannot collapse.**
`retired` is an object — issue, date, and the argument — so the refusal an
operator hits quotes the reason rather than a policy code. `trainable` is a bare
flag the builder reads. A third combination, **live and trainable**, is refused
where the declaration loads: that is #189 exactly, and this file is the last
place it is a sentence rather than a number somebody quotes. A set that states
no `trainable` flag at all is refused too — silence is not a default in either
direction.

**HumanEval+ is declared as a rootless external entry.** It has no contracts
here, so it is declared by its id space, which was already vendored beside the
pool gate (`tools/problems/humaneval-entrypoints.json`, 164 ids) — pointing at
that file rather than restating it means the screen and the declaration cannot
drift. `Instrument.root` is now optional and every root-shaped question answers
empty for it.

**The rigs refuse at `record_run`, and at the CLI ahead of the runtime check.**
`record_run` is the seam every dispatching path passes through — `measure.main`,
`campaign.run_stage`, both rigs — before the first draw, so a fourth driver
cannot route around it without also deciding not to record what it did. The CLI
check sits *before* `language.capability()` deliberately: whether this machine
can score the arm has no bearing on whether the project will measure it, and CI
runs Node 20 (no type stripping), so a guard behind that check would never have
been reached in a JS/TS test. `--selftest` and `--summarise-only` are not
measurements and still work.

**The task loaders are deliberately not guarded.** A retired tier still loads,
because rebuilding the prompt behind a released reply is the thing the release
is for. Guarding the loaders would have been the tidier-looking change and would
have made the release unusable.

**The corpus needed no re-pin.** Retirement does not change classification, and
adding HumanEval's ids changes nothing either — no run in the corpus carries
them. `pin.py --check` matches all 12,331 replies. That separation is the point
of writing provenance down rather than policy: the stamps say where a reply came
from and stayed true across a decision that reversed what may be done with it.

**Rebuilt: 1,544 examples over 184 problems** (1,405 train / 139 val, 1,442 TS +
102 PY), against 608 over 150 clean and #189's 738 over 20 it was then scored
on. Recorded at `records/corpora/training-release-2026-08-10/` — the manifest,
not the splits, which are 6.5 MB of text already pinned byte-for-byte in
`golden.json`.

**A task id turned out to be unique only inside its set.** `t01` names one
problem in `d1` and a *different* problem in `d2`, and before this the collision
was invisible because neither was drawable. Keyed on the bare id the two shared
one per-arm cap budget and one crowded out the other: **213 examples** and 14
problems' worth. Each example now carries an `origin` and the cap is keyed on
it. The split still hashes the bare id, deliberately — two sets sharing an id
are two problems, and holding out both when either is held out is the
conservative reading.

**114 released replies are drawable in principle and unresolvable in fact.**
`breadth-2026-08-06` recorded no tier and its ids fall in five sets at once, so
the contracts behind its replies cannot be identified. #230 made a tierless run
fatal; that stays fatal for a *live* rig, which is a defect that can still be
fixed, and becomes a counted drop for a retired set's frozen record. The refusal
to guess is unchanged either way.
