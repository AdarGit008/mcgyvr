Built #24: `src/mcgyvr/route.py`, plus `ladder.tiers[].attempts` in the config

**The boundary is the deliverable.** The ladder is ordered cheapest-to-dearest
in two nested ways — families (deterministic → local → api, ranked in the
catalog) and rungs inside a family (whatever the operator wrote) — and this
module walks only the inner one. `plan()` returns the rungs of *one* family with
the attempts each is allowed; `climb()` runs that plan against an attempt
function the caller supplies. An exhausted family ends the climb rather than
reaching for a dearer rung, because monotonic ascent, the global ceiling and the
verification upgrade are #43's rules and half of them living here would mean
neither module could be read on its own.

That is asserted twice, because "no path crosses families" is a negative:
behaviourally, against a ladder whose api rung is *usable* and never touched;
and structurally, by planning every family the catalog declares and checking
each step's family against the plan's.

**Entry is a floor question, and it is deliberately not resolved here.** A
contract's type names the family work may *begin* in, and a floor is satisfied by
a dearer family (`catalog._families_present` already says so). I left `plan()`
using the floor exactly as declared: if that family is empty, the plan is empty
and names why, and #43 acts on it. Pre-skipping to the cheapest non-empty family
would have been convenient and would have put "each family is entered at most
once" in a module that cannot see the other half of it.

**A decline is not a failure, and it does not cost a budget.** #81's rule — a
runner that cannot handle a contract steps aside rather than emitting a
plausible-but-wrong edit — needed a place in the sequencing, so `Verdict` has
three members and a `DECLINED` advances to the next rung without consuming an
attempt. That is why `Exhaustion` distinguishes `ALL_DECLINED` (nothing was
spent; says nothing about the family's ability) from `RUNGS_SPENT` (the family
was tried and could not) from `NO_RUNG` (a configuration fact).

**Budgets: config policy, contract ceiling, and one exception.** `attempts` went
into `TIER_FIELDS` rather than a new top-level block, following ADR-0008's
reasoning that policy references a rung by name — and it earns its place there,
because the one rung where a retry is clearly defensible is the dearest one,
which has nowhere to escalate to. The effective budget is
`min(tier.attempts, contract.limits.attempts)`: the contract's `limits` is
documented as a *hard ceiling on one execution*, so reading it as a cap rather
than as the budget keeps #24's "policy in config" true without redefining a
field that is public API in direct mode. The deterministic family gets exactly
one attempt whatever either says. The test that holds this drives two configs
differing in one number — asserting the default of 1 alone would pass against a
hard-coded 1.

**The family rule now lives in exactly one place.** `Catalog.family_of(source)`
was lifted out of `_families_present`; routing asks rather than restating it,
and a test checks the two answers agree for every rung of a config. Worth
recording *why* family is the right thing to route on: it is a **cost class, not
a location**. Re-pointing a rung between two local machines does not change it;
local-to-hosted does, and should. So `Rung` still carries no source, and nothing
above the seam learned where work runs — `route.py` imports `Rung` and
`SourceMap` and never `Endpoint`, so the seam guard needed no fourth argument.

**Capacity threads into every rung tried.** `dispatch(capacity=None)` is
unbounded by default, so a walk that bounded only its first rung would enforce a
source's limit on some of its own dispatches, which is the same as not enforcing
it. `Try.capacity` is handed to every attempt; that was the gap #23's handoff
named.

**Mutation-tested, seven mutations.** Dropping the deterministic one-attempt
rule, `min`→`max`, letting a decline consume the budget, dropping the family
filter in `plan()`, not returning on a pass, collapsing `ALL_DECLINED` into
`RUNGS_SPENT`, and counting declines as spent attempts each fail at least one
test.

**One real defect found and fixed while writing tests:** the empty-family
explanation quoted *every* skipped rung, so asking why the api family was empty
could hand back a local source's problem. It now filters to the family asked
about. The test that holds it needed a probe stub, because two families have to
be empty for unrelated reasons at once.

`mcgyvr pool` now prints each rung's family and attempt budget. Both are decided
before anything is spent, and the config file is the only place an operator can
see routing at all. This is also the first test the CLI's `pool` command has had.

## Left open

next: #43.

**#43 is the direct successor and this lane was shaped for it.** It receives
`Exhausted` and decides whether to enter the next family, which is the half
deliberately not built here. Three things it meets immediately:

1. **An empty plan is its input, not an error.** A deterministic-floor contract
   plans nothing today (the deterministic family binds no rung — it is tools),
   and a keyless install plans nothing for `api`. Both arrive as
   `Exhausted(NO_RUNG)` carrying a reason in words; ascent is what turns them
   into work.
2. **`ALL_DECLINED` should probably not count against a global ceiling.** No
   attempt was spent, so charging it would make a family that never ran look
   like one that failed. #24 keeps the distinction available; #43 is where it
   has to be used or deliberately ignored.
3. **#153 becomes live.** Family-rank ascent over a config-ordered ladder is
   exactly where an interleaved ladder starts executing in an order nobody
   wrote.

**#81 slots in without changing anything here.** Its runner is the deterministic
family's step, `attempts_for` already returns 1 for it, and `Verdict.DECLINED`
is the shape its "cannot handle this contract" answer takes. What it must
supply is the step itself — no config can produce one, because a rung's family
comes from its source's credential and a tool binds no source.

Not in scope and deliberately untouched: risk floors raising the entry family
(#16), draws per rung (#119 — a different axis from attempts: a draw is a fresh
sample, an attempt is a retry after a verdict), and any global attempt ceiling,
which #43 owns by name.
