# Session — lane/123 — 2026-08-03

## Did
Built the rung ADR-0010 adopted: a semantic check that resolves the calls on a
worker's added lines against the packages the target repository actually
installs, executed inside the per-task sandbox. It ships **reporting-only**, and
it is the first gate rung whose findings do not reject.

**The shape.** `SemanticCheck` (`gate/semantic.py`) mirrors `Acceptance` exactly
— a frozen dataclass bound to an entered sandbox, injected into `Gate.run`
rather than constructed by it — and runs at position 5, before acceptance and
after the adapters, which is the ordering ADR-0010 asked for: a sub-second
resolution pass has no business queueing behind a test suite. Findings are
filtered to `FileChange.added_lines` in the driver *and* again on the gate's
side of the sandbox, so the acceptance criterion is pinned where it can be
tested rather than trusted to what came back.

**Reports, does not reject.** `GateResult` gains `observations`: real,
line-attributed findings that are not part of the verdict. `blocking` is a
field on the rung and defaults to `False`. #129 bounds the false-positive rate
under ~0.8% at 95% on 358 chains — a thin sample, not a demonstrated zero — and
its four distinct flags were all correct platform-conditional code. Promoting
the rung is one field, and wants a wider sample first. That is the whole of what
Count 3 licensed and no more.

**The false-positive mitigation, built against the four sites #129 found.**
`check()` introspects the *live* interpreter, so correctly-guarded
foreign-platform code is indistinguishable from an invented API. Three rules in
`gate/semantic_driver.py` answer it: an `if` whose test is platform-dependent is
skipped whole (both branches — deciding which branch is foreign means evaluating
the test); a `try` whose handler catches `ImportError`/`ModuleNotFoundError` is
skipped whole; and chains rooted at `sys.stdout`/`stderr`/`stdin` are never
flagged, because those objects are rebound at runtime by design and in a
container the streams are pipes. `if TYPE_CHECKING:` is skipped because its body
never runs.

The platform rule **follows one hop through a relative import**, and that is not
incidental: click guards `os.startfile` with `if WIN:` where `WIN` comes from
`from ._compat import WIN`, so a rule that read only the file under check would
have missed both of the sites the measurement actually produced. Between the
three rules, all four observed sites are covered, and each has a regression test
shaped like the code that produced it. Every suppression is counted and returned
on the report — a rung that quietly stopped looking would report a clean pass it
had not earned.

**ADR-0011 — the resolver is staged, not installed.** This is the one place the
work diverges from #123's body, which assumed the tool enters the per-repo image
and asked for a version policy to manage the cache key that follows. I set the
policy by declining the premise. ghostcall's engine is four stdlib-only files
(CLM-0006); they are staged into the workspace for the length of one run and
removed in a `finally`, so `cache_key` keeps covering exactly the repository's
declared dependency set and `sandbox/image.py` is untouched by this issue. The
pin is `ENGINE_COMMIT` plus a sha256 per file in `gate/semantic.py`, verified
before anything is staged and fail-closed on mismatch — where closed means *not
running*, never rejecting. A test asserts those digests equal the evidence
`MANIFEST.json`'s and that the bytes on disk satisfy both, so re-pinning is a
deliberate edit to reviewed source rather than something a stray copy can do.
The three rejected alternatives (image install, a second copy under `src/`,
reimplementing the 173 lines) are argued in the record; the third loses on
evidence rather than effort — #129 measured *these bytes*, and a
reimplementation would not be the thing that was measured.

**Packaging.** The engine reaches a wheel through `force-include`, the mechanism
the task catalog already uses, because a record outside `src/` does not ship. A
wheel was built and inspected: the four files plus `LICENSE` land under
`mcgyvr/gate/_engine/ghostcall/` with matching digests. Only the stdlib-only
files are staged — the presentation modules and their three third-party
dependencies never enter the sandbox.

**Degraded environments never reject.** An import root that will not import, an
interpreter that is not there, a driver that dies or times out, a file that does
not parse: all are environment issues. The one that would make the rung
*vacuous* — every import failing, so nothing is ever flagged — says so loudest,
naming the roots and stating that the run cleared no call.

24 tests in `tests/test_semantic.py`, driven for real through the
temp-directory sandbox as the acceptance suite is. 649 tests, ruff, ruff format
and mypy --strict all green; baseline reports no blockers.
