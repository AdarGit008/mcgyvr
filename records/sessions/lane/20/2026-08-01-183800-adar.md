## Did

Delivered #20 — source map: endpoints, capacity, wire protocol — as
`src/mcgyvr/pool.py`, opening E3.

E1 already declared `Source(base_url, api, max_parallel, api_key_env)` and
`Tier(name, source, model)`. What was missing was the **seam**: the one place
that resolves a rung to somewhere to run, so that nothing above it has to know.

- **Above the seam:** `Rung(name, model)` and nothing else — no URL, no protocol,
  no source name. This is what makes "a tier moves between sources with a config
  edit and no code change" structurally true rather than a convention callers
  are asked to respect. A caller cannot come to depend on where work ran because
  the type it holds cannot say. `SourceMap.bind()` is the only producer of an
  `Endpoint`.
- **Below it:** `Endpoint(source, base_url, protocol, max_parallel,
  credential_env)`. `Protocol` has exactly two members; `openai` covers vLLM,
  llama-server, LM Studio, TGI and the hosted providers, so a new backend is a
  config entry, not an integration.
- **Degradation is structural, not fatal.** A source whose credential is named
  but absent from the environment cannot serve, so its rungs are `Skipped` with
  the reason in words and the rest of the ladder still works. Everything
  unusable yields an *empty ladder that can explain itself*, not an exception —
  the caller decides what that means, since for a keyless install it may be
  exactly what was configured. `bind()` separates an unknown rung
  (`UnknownRungError`) from a skipped one (`SourceUnavailableError`): different
  mistakes, different messages.
- **Credentials are named, never held.** `Endpoint` carries the variable name;
  `credential()` reads the value at dispatch. A secret never sits in a dataclass
  and so cannot reach a log through a repr. Presence is checked at map build (so
  an unusable rung is skipped early) and the value resolved late — the resulting
  window is deliberate and tested, and it fails loudly rather than dispatching
  unauthenticated.
- Roles (`orchestrator`, `verifier`) cross the same seam via `SourceMap.role()`.
  An unbound role is an ordinary `None` — "unset until something needs it" —
  while a role on an unusable source raises, because that one was asked for.

Exposed as `mcgyvr pool`. 18 tests; suite 431 green; `make lint` clean; gate
reports no blockers.

**Scope held narrow at three edges, deliberately.** A tier naming an undeclared
source is a typo and E1's loader already rejects it at load time
(`config.py:736`) — this module does not re-litigate it, and the degradation
here is only for *declared but unusable*. Live reachability is #22: it needs
short timeouts and per-run caching, which structural resolution does not.
Capacity is *carried* (`Endpoint.max_parallel`, and the endpoint names its
source) but not enforced — #23 acquires at this same seam, which is why the
source name is on the endpoint rather than the rung.

**One test I had to fix, worth recording.** The architectural guard for "nothing
outside the seam reads a source" was first written as a substring grep for
`Endpoint(` across `src/`. It failed — on `detect.py`, which has its own
unrelated `Endpoint` (a well-known local address to *probe*, which exists before
any config does). The grep was the wrong instrument, not the finding: it now
parses imports with `ast` and asserts nothing outside `pool.py` imports
`Endpoint`/`RoleBinding` from `mcgyvr.pool`.

## Left open

- **Name collision: `pool.Endpoint` vs `detect.Endpoint`.** Two unrelated types
  sharing a name in one codebase. They are genuinely different concepts (a
  resolved dispatch target vs an address to probe), and `Endpoint` is the right
  word for the pool's. Renaming `detect`'s is another lane's surface, so it was
  left alone rather than widened into this PR. Worth settling before #21/#22
  make both names common.
- `mcgyvr pool` prints the ladder and skip reasons but **not** endpoints, on
  purpose — the command answers "what can run", and a rung that cannot names its
  source in the reason, which is when that fact starts to matter. Note that
  `mcgyvr config` *does* print sources; that is a config viewer showing the user
  their own file, not a dispatch path, and the seam is about dispatch.
