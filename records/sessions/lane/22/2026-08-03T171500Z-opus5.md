# Session — lane/22 — 2026-08-03 (local vs hosted)

## Did

No behaviour change. Made explicit something the first pass left implicit, after
the owner asked whether "a machine is switched off" meant a local backend or an
API provider — a fair question, because the answer is *both*, and the module was
written as though it were one thing.

**The two kinds fail differently, and the classification is asymmetric because of
it.** That was true before and undocumented, which is the worst combination:

- A **local backend** — Ollama, llama-server, vLLM, LM Studio, TGI on hardware
  the user controls — characteristically fails by *not running* (connection
  refused, instant) or by the machine being *off or asleep* (the whole timeout).
  It is also the kind that produces the awkward **404**: a small server may
  implement `/v1/chat/completions` and never implement `/v1/models`.
- A **hosted provider** characteristically fails by *rejecting a key* that is
  wrong, expired or revoked (**401/403**), by *outage* (5xx), or by this machine
  having no working internet (timeout). It essentially never 404s at the model
  listing, because publishing one is table stakes for a commercial API.

So **the 401 arm exists for hosted providers and the 404 arm exists for local
backends**, and each reads as an over-reaction if you only picture the other
kind. That is now written down in the module docstring, in the CHANGELOG, and —
more usefully — in the tests, which are arranged as a deliberate pair with a
comment saying what each case is *for*.

**What I did not do, on purpose: branch on the distinction.** Nothing reliably
separates the two. A local server behind a reverse proxy can require a key; a
self-hosted vLLM can sit on a public hostname; "is it localhost" is a heuristic
that would be wrong for every LAN box. Introducing a `kind:` field would be a
config change with its own decision to make, and it is not #22's. The
distinction is therefore descriptive — it explains the design, and no code reads
it.

One gap the pairing exposed and I closed: the 401 arm is reachable by a
**keyless** source too, and the reason text has to stay actionable there. It
already said "no credential is configured" rather than interpolating a null
variable name, but nothing held that, so a test does now — it would have been an
easy thing to regress into `$None`.

Also drew the line against `mcgyvr.detect`, which is easy to confuse with this:
`detect` is install-time and local-only, sweeping *candidate* default ports
(11434, 8080, 8000, 1234, 3000) to see what this machine happens to run. This
module probes the sources a config actually *declares*, local or hosted, once per
run.
