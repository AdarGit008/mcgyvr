## Found

**The Node guard was checking for the wrong thing, and CI proved it.** The
acceptance-running tests skipped on `shutil.which("node")`. Presence is not the
predicate: `accept.mjs` imports `./solution.ts`, so the tests need a Node that
*strips types*, which is unflagged only from 23.6 and 22.18. CI's baseline job
pins Node 20 for the gate's own runtime, so the guard skipped nothing there and
all four tests failed inside BUILD-05 — "Task 1 passes on a clean checkout" —
which is a blocker. The lane went red on its first push having been green
locally, because this machine has Node 24 and `make check` never asked whether
that mattered.

**The same assumption was in the rig, and there it would have been worse.** A
sweep on an older Node fails every task identically, and the symptom — twenty
red rows against a TypeScript task set — is indistinguishable from a model that
cannot write TypeScript. That is not a weak result; it is no result that reads
as one. `node_runs_typescript()` now runs a `.ts` file rather than parsing
`--version`, and `--selftest` and a sweep refuse up front with the reason. The
tests skip on the rig's own predicate, so there is one definition of a usable
Node rather than two.

The baseline job's Node pin is left at 20. It is deliberate — the gate's runtime
— and the fix makes an environment that cannot run acceptance skip honestly
instead of demanding every environment match this one.
