## The gap was one function's scope

`_placement(resident, model)` matched one row of `/api/ps` and returned. Every
other resident's `size_vram` was read in the same response and discarded. So a
co-residency cell recorded that its neighbour was **listed** and never where
the neighbour **landed** — and `coresidency_arranged`, built from an HTTP 200
and a name, said `true` either way.

The measurement that makes this concrete is session 18's, not this session's:
ollama answers `load_http=200` with **93% of the model on the CPU**, and the
spilled model still returns correct code in seconds. "It loaded" and "it fits"
are different facts and only the first was written down.

**ollama cannot report this about itself.** Its pre-flight fit check in
`server/sched.go` is guarded by `len(s.loaded) > 0` — its OWN models — so a
foreign allocation is invisible to it and llama-server auto-fits into whatever
is left. The reading has to be taken here or it is not taken.

## The second half was the one that was nearly missed

`run.py`'s post-ramp re-read exists because BL-6 found neighbours evicted mid
-curve. It compares `spec["coresident_with"]` against `backend.residents(host)`
— a list of names — and writes `coresidency_after.held`.

**A name list catches the neighbour that LEFT and nothing else.** One that
stayed and spilled is still listed, under its own name, with its full `size`
beside a `size_vram` nobody read. So `held: true` was reachable for a neighbour
sitting 93% on the CPU: the same silent nothing at the other end of the
measurement, one function away from the one #335 named.

It is a second producer and a second read, recorded beside the verdict rather
than folded into it — a second read is a second moment, and the two are named
apart for the reason the card's `before`/`after` readings are.

## Recorded, never gated — and the reason is the campaign's

Neither placement enters `ok`. A spilled neighbour is the frontier this
campaign exists to map; a claim that refused it would refuse its own question.
That is the owner's standing correction from session 16 applied where it lands:
**declared pre-state must match or refuse; everything else recorded, never
ignored.** Placement is not declared pre-state. It is the result.

**Absent is not zero and it is not one.** A backend that cannot report
placement writes `null`. `vllm.residents()` still does not exist — contract
defect 5, untouched — so a vLLM cell's placement is absent rather than a
number, and that is what bounds this box to what ollama can see.

## What landed

  about a neighbour. `_placement` keeps its contract exactly, `{}` included.
- `_placements(resident)` over every `/api/ps` row; `placements(host)` for a
  caller holding only a host, public for the reason `residents` is.
- `claim` records `resident_placements` per attempt. One `/api/ps` response
  already read, so it costs nothing beyond the arithmetic.

  cannot be added to a producer and dropped by a sink.
- Four named checks in `tests/test_serving.py`, listed in a dated block under
  §7 of `docs/run-contract-2026-08-22.md`, where contract defect 1 is closed.

## A correction about my own instrument, which is the sixth instance

The first mutation sweep I ran was a bash harness that reported **all seven
mutants GREEN** — "the check does not reject" — on checks that in fact reject
every one of them. I did not take the result at face value, re-ran one mutant
by hand, saw it fail correctly, and rewrote the sweep in Python, where all
seven come back red.

That is a false negative, which is the safe direction, and it is the **sixth**
instance on this lane of a result that came from how a check was run rather
than from what it asserts — and the first where the affected instrument was the
sweep itself rather than the code under it. The lesson is the lane's existing
one, one level up: **a sweep that reports green is making a claim, and it needs
its own positive control.** The Python driver has one by construction — it
prints the failing assertion for each mutant, so a green result cannot be
mistaken for a run that selected no tests.
