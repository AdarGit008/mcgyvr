## Did

Renamed `detect.Endpoint` to `detect.ProbeTarget`, closing the name collision
#20 introduced. `DEFAULT_ENDPOINTS` becomes `DEFAULT_PROBE_TARGETS`, and the
`probe` / `probe_all` / `detect` parameters follow (`endpoint` → `target`,
`endpoints` → `targets`).

The two types were genuinely different ideas wearing one name:

- A **probe target** is a *candidate* address that may have nothing behind it.
  It exists before any config does — the default list is just the ports each
  backend conventionally ships on.
- A **`pool.Endpoint`** is somewhere a rung is *configured to run*, and exists
  only once there is a config to resolve.

Sharing "Endpoint" made "where might something be" and "where does this rung
run" read as the same idea, which was going to get more expensive: #21 (runners)
and #22 (availability probing) both handle both concepts. `ProbeTarget`'s
docstring now names the distinction and points at `pool.Endpoint`, so the next
reader does not have to rediscover it.

No behaviour change. 483 tests green, `make lint` clean, gate no blockers.

**Why this is its own lane.** The rename was written on `lane/20` and pushed
about a minute *after* PR #104 merged, so it never reached main. Continuing on
`lane/20` was not an option: its anchor #20 is closed, which puts the gate into
DIV-01 ("issue closed, lane still active") — 2 blockers. Filed #106, claimed
`lane/106`, cherry-picked the commit. Worth remembering as a general rule:
**once a lane's PR merges, that lane is spent — a follow-up needs a new issue
and a new lane, not another commit on the old branch.**

**One thing the rename did not touch, deliberately.** `sandbox/base.py` has an
`endpoints=` parameter (URLs a sandbox may reach). It is a third, unrelated use
of the word, but it is not a *type* and does not import either `Endpoint`, so
renaming it would be churn without a collision to resolve.
