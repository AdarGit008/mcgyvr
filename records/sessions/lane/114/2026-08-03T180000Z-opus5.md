# Session — lane/114 — 2026-08-03

## Did

Built #114: `LanguageAdapter.locate_type_check_command(repo) -> list[str] | None`,
abstract on the interface and implemented on both adapters. ADR-0006 had already
decided everything hard, so most of the work was refusing to be helpful.

**Python** finds a checker in the files that checker itself reads —
`[tool.mypy]` in `pyproject.toml`, `mypy.ini`, `.mypy.ini`, a `[mypy]` section in
`setup.cfg`; `[tool.pyright]` or `pyrightconfig.json`. That is slightly wider
than the issue's wording, deliberately: ADR-0006 turns on *what the repository
declared*, not on where it chose to write it down, and a project with `mypy.ini`
has declared mypy every bit as much as one with a table. **JS/TS** treats the
presence of `tsconfig.json` as the declaration and yields `tsc --noEmit`.

**Parsed, not grepped, and that is the whole difference between working and
harmful.** `locate_test_command` next door does `"pytest" in text`, which is fine
for its purpose. Here a substring match fires on a dependency pin
(`dependencies = ["mypy>=1.0"]`), on a comment, and on `[tool.ruff.lint`
`.flake8-annotations] mypy-init-return`. Each would fabricate a type-check
command for a repository that runs no type checker, and a fabricated acceptance
command fails in the sandbox as though the worker's change were at fault. So
TOML goes through `tomllib`, INI through `configparser`, and a `[mypy-vendored.*]`
per-module override in a file that never configures mypy itself is correctly not
a declaration. An unparseable manifest answers "no" rather than raising — a
malformed file is the target's business.

**The command is bare, and that is a decision rather than an omission.** `mypy`
with no arguments reads the repository's own `files`/`exclude` and checks what
the repository said to check. Adding a path would substitute mcgyvr's idea of the
scope for the one the project wrote down — the same error as adding a flag, in a
different costume. `--noEmit` is the single argument anywhere in this lane, and
it is not a strictness flag: it is the difference between running a check and
running a build, and it spares a repository with an `outDir` having a gate step
scatter artefacts through its tree.

**Two guards, because the acceptance criteria are absences and an absence is easy
to assert vacuously.** No forbidden flag appears in any arm's output. And nothing
in the locator or any helper it reaches calls `run`, `Popen`, `import_module`,
`eval`, `exec`, `compile` or their neighbours — checked by parsing the functions'
own ASTs rather than grepping, so the guard is about what the code does and not
which words appear in it. **I mutation-tested that one**: inserting a
`subprocess.run` into `_declares_pyright` fails it with
`_declares_pyright: ['run']`, and removing it passes. A guard that cannot fail is
the thing #133 taught me to check for.

`make check` green: 756 passed, lint and mypy clean. Verified against real trees
as well as fixtures — this repository yields `["mypy"]` (its `[tool.mypy]` sets
`files`, which is why bare works), and the pinned `immerjs/immer` clone yields
`["tsc", "--noEmit"]`.
