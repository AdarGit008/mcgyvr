# ADR-0016 — fixtures capture what the parser reads, not what the run did

Status: Accepted
Supersedes: none
Superseded-by: none
Date: 2026-08-06

## Context

#184 established that mcgyvr generates its parser's exact input distribution —
real worker replies, on real hardware, at real cost — runs `parse_reply` over
every one, and discards the population. The JS/TS sweep alone produced 160 real
replies and kept none; #174 (a well-formed refusal that parsed as file content)
is what the discard costs, and its fix shipped with ten more *constructed*
fixtures, bounded by what their author imagined. The issue says: keep the
replies. This record decides *what, exactly, gets kept*, because the #175
survey found the same idea shipped twice with opposite fates, and the variable
that separated them is the thing captured.

**The trajectory that died in six days.** OpenHands
(`OpenHands/software-agent-sdk` @ `b35c2fee8`) captured six real Sonnet-4
completions, committed them, and built a replay test on them — the exact
record/replay shape #184's first draft pointed at. Six days later they
overwrote the captures with hand-authored mocks, reason given in the commit:

```text
Real fixture data may have different tool call sequences than current agent
```

Eleven months on, `test_hello_world_with_real_llm_data` still passes and reads
none of the real data its name promises. The capture was coupled to the tool
schema and agent configuration at capture time; the first change to either
invalidated it; and the maintainers did the economically rational thing, which
was to stop capturing. A fixture format that decays faster than the system it
tests converges on hand-authored fiction with real-sounding names — worse than
no capture, because it testifies to a realism it no longer has.

**The corpus that is still alive years later.** aider (@ `5dc9490b`) keeps
99,961 lines of raw model replies and diffs them whole against a golden file
holding 577 parsed blocks — including **33 recorded parse failures, kept as
gold rather than excluded**. The corpus is raw reply text: the byte stream the
parser receives, nothing about what the surrounding system did with it. It
invalidates only when the reply format itself changes — which is exactly the
event a parser's test corpus *should* be sensitive to, and the only one.

The general form: a captured artifact is stable against every change except
changes to the interface it crosses. Reply text crosses one interface —
`parse_reply`'s — and so has one invalidation trigger. A trajectory crosses
every interface in the run — tool schema, prompt template, agent loop, model
config — and inherits all their invalidation triggers at once. moatless's 24
captured test-output logs (asserted down to stack frames, still valid) and
micro-agent's `captureLlmRecord` sit on the same axis: the durable captures in
the survey are all inputs to a parser; the decayed one is a recording of a run.

## Decision

**Captured fixtures record the raw text the parser receives, never the run
that produced it.** For #184 and any successor: what is written is the reply
body exactly as `parse_reply` gets it, plus minimal provenance — model,
condition, a pointer to the run record — sufficient to answer "where did this
come from" under #118's evidence discipline. What is *not* written: tool-call
sequences, message histories, agent state, or anything else whose validity
depends on how the system that captured it was configured.

**Parse failures are corpus, not noise.** A reply the parser could not handle
is kept and pinned as gold — the expected outcome for that input *is* the
failure, until someone improves the parser and re-pins deliberately. aider's 33
are the model; #174's refusal is the local proof that the unhandleable shapes
are the ones worth the most. Excluding failures from the corpus reintroduces
the author-imagination bound the corpus exists to escape.

**The corpus is asserted whole.** One golden comparison over the full set, in
the aider shape, rather than a hand-picked fixture per test. A per-test
selection is a curation, and curations drift toward the shapes the curator
understood.

## Rejected: record/replay of full runs

The micro-agent shape #184 originally cited, and the stronger-looking option —
a replay reproduces the *system*, not just the parser. It loses on the decay
mechanism OpenHands demonstrated at full scale: the recording couples to every
schema it passed through, mcgyvr's own tool and prompt surfaces are precisely
what its lanes change most often, and a corpus that each refactor invalidates
is a corpus that gets regenerated by hand until it is fiction. Replay testing
of whole runs is not refused forever; it is refused as the *fixture format for
worker replies*, where the durable alternative costs less and tests the
component that actually broke in #174.

## Rejected: keep hand-authored fixtures as the corpus, capture nothing

The current state, continued. `tests/test_worker_reply.py` opens with a
docstring claiming its refusals are "real shapes a local worker produces," and
under this repository's own filter that claim is unverifiable — nothing links
any fixture to a run. We would reject that sentence from a third party; #174
is the counterexample that got through it. Hand-authored cases remain welcome
*additions* — an adversarial imagination is a real instrument — but the
population the parser is measured against must be the one it actually faces.

## Consequences

- **#184's implementation has its shape fixed in advance:** a capture point at
  the reply boundary, raw text plus provenance, a golden file diffed whole,
  failures pinned as expected outcomes. The issue's open design question is
  discharged by this record; what remains is construction.
- **Capture is nearly free at the point of generation** — the bundle harness
  already holds the reply text at the moment it records `parse_error`; the
  change is writing it down rather than dropping it.
- **The corpus grows monotonically and cheaply.** Every measurement run is
  also a corpus contribution, with no curation step to skip and no schema to
  keep in sync.
- **What this gives up:** end-to-end replay of recorded runs, and with it the
  ability to regression-test the agent loop against a captured session.
  Accepted: that test decays in days (measured, not argued), and the loop is
  tested by construction elsewhere.
- **What this bets on:** that the parser boundary is where reply realism pays.
  If a future defect slips through *because* it lived in the trajectory rather
  than the reply text, this record is the one to amend — with that defect
  attached as the case the format must now cover.
