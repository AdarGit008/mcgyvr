## Did

`tools/deps/wire.py` — add, remove and list issue-dependency edges, with every
write proven against the live graph.

The defect it closes: `gh api -f issue_id=N` sends a **string**, the endpoint
wants an **integer**, and the 422 is invisible under `--silent` — the flag anyone
looping over dozens of edges reaches for. Wiring the ADR-0018 restructure on
2026-08-09, roughly twenty edges reported as written and none were. A second
failure had the same shape: one issue was missing from a locally cached
number→id map, so the body became `issue_id=""` and failed the same silent way.

Three properties, each aimed at one of those:

- **`-F`, not `-f`**, so the 422 cannot happen by construction, stated at the
  call site because the failure is invisible rather than obvious.
- **Ids resolved from the API at call time**, never cached — a stale or
  short-a-page map degrades into exactly the silent failure above.
- **Every mutation read back against the live graph.** A write that did not land
  is a named failure and a non-zero exit. Partial failure is reported per edge,
  since a loop that half-worked is the case that needs naming.

Verified live rather than by inspection: a block/unblock round-trip on #235, and
a bogus blocker exiting 1 with the reason printed instead of a silent 0/1.

Not `--silent` anywhere in the module, deliberately — the discarded write is the
whole subject.
