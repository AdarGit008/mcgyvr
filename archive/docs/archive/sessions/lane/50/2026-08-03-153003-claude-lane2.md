## Did

The judgment step, built around one question: how little of a contract may a
model's opinion author? The answer generalises ADR-0007 from signatures to the
whole document. A model decides **relevance** — the kind of work, the file it
lands in, which of a file's symbols the target needs. The repository decides
**fact**. So the seam is not "the model writes a contract and we check it" but
"the model writes references and the index resolves them": a `Proposal` names a
symbol, and there is no field on it that could carry a signature.

Four properties are structural rather than remembered:

- **Every emission came through `contract.loads`.** A proposal is assembled into
  a document, serialised and parsed by the same entry point direct mode uses,
  and that is the only way out of the module. "An emitted contract is one the
  direct-mode API accepts" is a property of the code path, not a claim a test
  chases. A document the loader rejects becomes a refusal carrying the loader's
  own message — which already names the field and states the fix, so the
  decomposer never paraphrases a rule it does not own.
- **A dep the index cannot state is refused, never described.**
- **An undecomposable request explains itself.** No fallback wraps an unparsed
  prompt in one big contract. A degenerate single contract is worse than a
  refusal because it looks like a plan.
- **Nothing unservable is emitted**, checked with the catalog's own
  `servable()`. The refusal names what the ladder can run.

Ids derive from the work, not from a clock — the whole reproducibility claim
rests on that one field. Two identical proposals collide by construction and the
duplicate is refused rather than given an ordinal.

`context.max_input_tokens` is sized off `worker_view()`, closing what #115 left
open. Floored at the schema default, no margin: the estimator's error band is
#117's to measure, and a margin invented here would be the unsourceable constant
ADR-0007 rejected. `_estimate_tokens` became public so the budget is sized with
the same proxy the read plan spends against.

## Found

The contract schema is stricter than the issue's scope implies, and correctly
so — it rejected the first fixtures for missing `stop_conditions` on a
model-executed type. That is the right split and it stayed: the decomposer
invents neither stop conditions nor acceptance commands, because both are
judgements, and a module that filled them in would be fabricating the very
things the gate later relies on. Two tests hold that.

The shipped catalog has **no type that starts on `api`**, so a keyless install
refuses nothing and the ladder-serviceability path could not be demonstrated
with one. The configuration that genuinely cannot serve model work is one with
no rung bound at all. Worth knowing before #16 sets routing floors: today the
`api` family is a vocabulary the catalog never requires.

## Left

**The judgment seam has no default binding, and that is the deliberate stopping
point.** #25 — the worker prompt bundle and single-file output protocol — is
still open, and it owns prompt assembly and reply parsing. Building a second
prompt-assembly path here to call a model would duplicate the module that has
not been written yet, which is the doubling ADR-0001 boundary 8 exists to
prevent. So this lane ships the structure and the refusals, and the
model-backed proposer binds when #25 lands.

No CLI command. A `mcgyvr decompose` would need proposals from somewhere, and a
proposals file would become a second public format alongside the contract
schema — API surface #50 did not ask for. The seam is reachable from the package
API; the CLI waits for a bound proposer.

What is not settled is whether decomposition is *good* — whether the units a
proposer names are the smallest ones a rung can actually complete. Nothing here
measures that, and #113's harness is where it becomes measurable.
