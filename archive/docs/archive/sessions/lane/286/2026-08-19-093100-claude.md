### The result that runs through all of them

**A throughput plateau is not a slot limit.** A scheduler limit
(`--max-num-seqs`, `-np`) and a throughput saturation point coincide only when the
limit binds before the hardware does, and this lane has already measured a
divergence — ollama on srv2 with `-np 1` reads a plateau of **2** at 512 tokens.
So the output splits into `declared_slots` (a read) and `saturation_n` (a
derivation, always carrying the token count and cutoff that produced it). There is
no `width` field any more, and `batches` is retired.
