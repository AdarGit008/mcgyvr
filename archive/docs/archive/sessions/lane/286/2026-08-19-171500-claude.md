### The interrupt path — `faf9124b`, not from any review

Stopping the driver left srv2's vLLM container up with **11,078 MiB** resident
until it was cleared by hand. `run.py` releases at the end of a survey and
`calibrate.py` between arms; an end that never arrives runs neither.

`launch.py` now emits a driver that traps INT and TERM, releases every backend
on every host, and releases once more after the phases. **The phases run
backgrounded behind an interruptible `wait`, and that is the whole point:** `sh`
will not run a trap while a foreground child is running. Measured on the first
version — SIGTERM with a 300-second phase in flight ran the release 300 seconds
later, which over eleven hours is no handler at all. Measured on the shipped
version: **63 s from SIGTERM to exit against a 600-second phase**, all of it the
ssh release itself, with the phase's children gone and all four host/backend
pairs released. SIGKILL is not survivable and is not claimed to be.

`launch.py --release` is the entry point, usable by hand at any time.

### A rig question that was asked and answered

Whether srv2 should stop running vLLM as root — Docker non-root, or native like
srv1. **Neither, and nothing was changed.** srv2 already has a working non-sudo
teardown: `docker stop` at `vllm.py:264`, and `adaramir` is in the docker group
on both rigs. The root-owned pid is the container's process as seen from the
host, which is Docker's default. Going native would mean installing torch on a
rig that has none and changing the instrument days before a campaign, for a
cosmetic win. Revisit only if the root-owned cache actually bites.
