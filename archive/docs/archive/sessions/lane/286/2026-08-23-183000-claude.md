# Session — lane/286 — 2026-08-23 (twenty-fifth)

**#329's rig arm ran, the strict xfail came off, and the launcher — the one
alternative explanation that could be removed without buying hardware — was
worth 0.06 on a gap of 11.6.** One issue's last box, one seam, one journal.

## The decision the session opened with

`serving_build` is `vllm 0.26.0` on both launchers, because that string is the
package's version and not the build's. So the contrast #329 built would have
**passed its identity gate on a pip-against-container pair**, which is the
confound the issue exists to remove, and no field on the row would have said
so. Three ways were put to the owner; **the owner chose docker on both**.

That needed a seam. `vllm.launcher` returns `pip` for any host answering
`command -v vllm`, and since 2026-08-22 srv1 answers both probes — so detection
could not put srv1 on the container arm at all.

## What landed

**The declared launcher** (`vllm.py`): `DECLARED_LAUNCHERS`, `declare_launcher`,
and `--launcher {detect,pip,docker}` on `calibrate.py`. Four properties, each
because leaving it out is a way to measure the wrong thing:

- **Declared, not configured.** The docstring's original warning still holds —
  a config that states a machine's property can state it wrongly — so a
  declaration is **verified with the probe detection uses** and refuses when the
  host cannot honour it. Falling back would run the arm on the launcher the
  declaration exists to exclude and record `pip` as if it had been chosen.
- **One call site is not enough.** `launcher()` has two consumers: `_start` and
  `weights_sha256`, which picks whether torch runs inside the image or on the
  host. A declaration honoured by the first alone serves srv1 from the container
  and hashes its checkpoint with the host's torch — one cell, two builds.
- **The row says which it was.** `launcher_declared` on the launch row, through
  both disposition tables. Two detections that agree describe the rigs; one
  declaration honoured twice describes the run, and `launcher` alone says
  `docker` either way.
- **`none` is a detection result, never a declaration.** Refused at the
  declaration, where the run is described, rather than as a `KeyError` later.

Five checks in `tests/test_cross_rig_claim.py`; **five mutants, one edit each,
all five killed** — including the digest one, which is the only mutant that
produces a plausible journal.

## Checked before the run rather than after

The ramp declares `gpu_memory_utilization 0.85` — 5,222 MiB on srv1 against
10,444 on srv2, exactly the card-relative declaration ADR-0039 rules against —
so whether srv1's 3.76x was a KV budget was worth asking before spending rig
time. **It is not:** D7 predicted srv1 would cap at `kv_cache_max_concurrency`
5.314 and both rigs measured `saturation_n` of exactly their configured 16
(`calibration-2026-08-19/README.md:975-990`), so the budget never limited
concurrency on either side. The fraction was kept, because changing it would
have stopped this being a re-take of the cell the sentence was read off.

## Two figures the arm produced on the way

- **srv1's first container launch: 83.5 s against its pip launch's 33 s** — the

- **The digest ran inside the image on both hosts**, because it follows the

## Kept

- **A gate that cannot see the difference it exists to hold fixed is worse than
  no gate**, because it returns an answer. `cross_host_contrast` checked
  `serving_build` for equality and would have reported two comparable sides.
  The field it needed did not exist; the fix was the field, not the comparison.
- **The cheap check before the expensive one.** The KV question above cost one
  grep of a record that was already in the tree, and would have voided the arm
  if the answer had gone the other way.
