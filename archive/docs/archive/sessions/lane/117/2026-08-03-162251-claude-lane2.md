## Did

`estimate_tokens` is four characters per token. Nothing knew what that cost.

The corpus is **captured, not constructed** — #117 says to measure "through the
injectable `estimate` seam", and that is literally the method: a recording
estimate is handed to the real `explore()`, so all 2,387 units are strings
production actually asked the estimator to count. Nothing reimplements a window,
and queries are each frame's own exported names rather than a hand-picked list.
Frames are the reach corpus's, reused rather than re-pinned.

**The proxy under-counts more often than it over-counts, and the size depends on
the vocabulary.** Qwen2.5-Coder median -0.8% (p05 -17.6%), gpt-oss -0.5%,
DeepSeek-Coder-V2 -17.9% under-counting 94.9% of units. A 100,000-token
vocabulary splits the same text into more tokens than a 151,643-token one, and
four-characters-per-token has no way to know which model is on the other end.

The band is **language-dependent** (JS/TS -7.9% where Python is +2.2% on Qwen),
which is why #117 asked for it per language. And **worker-view documents are
under-counted on 100% of units on every vocabulary** — the single most relevant
figure here, because that is exactly the text a prompt budget is enforced
against.

`check_prompt_fits` reserves 32% against a proxy count and nothing against a
real tokenizer's, and says which it enforced with. Only the under-counting tail
is reserved: over-estimation costs context, under-estimation ships a prompt the
backend refuses, and they are not interchangeable.

## Found

**Three vocabularies, not four.** Qwen3-Coder-30B-A3B ships Qwen2.5-Coder's
vocabulary and produced identical counts on all 2,387 units. Established by
comparing counts rather than reading model cards, and reported in the summary,
because counting both as independent evidence would have inflated what the band
rests on.

**A guess recorded as refuted.** The extreme unit is -73.3%, about 1.07
characters per token, and the obvious explanation was non-ASCII text. It is
wrong: `non_ascii_share` is a column precisely so it could be checked, and that
unit is 0.0% non-ASCII. The tail is dense structured literals — code shaped like
data. Only 4 of 2,387 units carry meaningful non-ASCII at all.

**One existing test changed meaning**, and it should have: 4000 estimated tokens
against a 4192 budget used to pass. The same text could really be 5280 tokens,
and admitting it is how a prompt reaches a backend that refuses it.
