## Found

**The parser cannot judge a refusal without knowing the target, and the issue's
own two shapes prove it in opposite directions.** `# I cannot complete this
task.` is a comment in Python and a *heading* in Markdown. `{"status":
"blocked", "reason": "unsafe"}` is a refusal in a `.py` file and a perfectly
good `.json` one. The same bytes, decided by the destination — and nothing in
the reply says which. So `parse_reply` gained an optional `target`, and the
check runs only when it is given. This was not in the issue's framing; it is
forced by it. Cheap to add because `parse_reply` has **no production caller
yet** — only the re-export in `worker/__init__.py` and tests.

**The languages judged are the gate's, not a new table.** Python (`.py`,
`.pyi`) and JS/TS, mirroring the adapters at #35/#36. A language the gate cannot
check is one this module has no business forming an opinion about, and an
unrecognised target is left alone rather than judged badly — a missed refusal
costs one task, a wrongly refused file costs every task of that shape. Chose to
duplicate the extension tuples rather than import them: making the parser depend
on the gate for a question about *text* is the worse coupling, and the cost is
stated in the comment.

**The routing behaviour #174 asks for already exists — under a name that does
not fit.** `route.Verdict.DECLINED` does exactly the right thing: `route.py:487`
breaks out of the rung immediately instead of retrying it, and the decline costs
the rung's attempt budget nothing. That *is* "escalate now, do not retry this
rung with notes". But its documented meaning is "it **did not try**, because the
contract is not work of a kind it can do" — #81's rule, written for a
deterministic tool stepping aside before spending anything. A model that emitted
a fenced refusal did try, and spent its tokens. Worse,
`Exhaustion.ALL_DECLINED` is documented as saying "nothing about the family's
ability at all", when a family whose every rung refused has said something quite
specific. Left undecided deliberately and recorded on #41, because a verifier
refusal and a worker refusal hit the same enum from two sides.

**`escalate.Opinion` already carries the three-way split** (`AGREED` / `REFUSED`
/ `UNUSABLE`) that the analogous verifier path needs. Nothing to build there;
noted on #41 so it survives implementation.

## Left

**Stubs are ruled out, so the gap #132 measures is still the gap.** Where no
runnable check is declared, a stub still lands and still reads as success. This
issue narrows the hole; #146 and #132 are what close it.

**Block comments are stripped only when they occupy whole lines**, anchored at
line start so a `/*` inside a string cannot swallow a real file. A refusal
written as a trailing block comment after real code would not be caught — but it
would also not be a refusal, since real code is present.

**No production caller passes `target` yet**, because there is no production
caller. The check is inert until the worker path is wired, and whoever wires it
must pass the contract's target or silently get the old behaviour. That is the
one way this lands and does nothing.
