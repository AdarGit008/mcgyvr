# Session — lane/144 — 2026-08-03

## Did
Built the JS/TS bundle-size experiment (#144) and did not run it.

**The instrument is complete; the sweep has no worker.** `tools/bundle/` holds
the four-condition ladder, 20 JS/TS task contracts with reference solutions and
runnable acceptance, and a rig that dispatches through mcgyvr's own runner. What
is missing is the one thing this machine cannot supply, and the README says so
in the file rather than leaving it to an empty results directory.

**c2 is the shipped bundle, byte for byte, enforced twice.** The rig refuses to
dispatch if it is not, and a test says the same without a worker. That is what
would make a future number quotable about `prompts/javascript.md` rather than
about a file resembling it — the property `python.md` already has against the
measured `c2.md`.

**The ladder is nested and the sizes are close to the Python one** (369 / 1877 /
8883 against 440 / 1972 / 8342). Nesting is tested, because a c1 that differed
from c2's opening in wording as well as length would be measuring two variables
and reporting one.

**Dispatch and parsing are the shipped path.** `Request` through `runner_for`,
replies through `parse_reply` with the completion's real stop reason. A reply
mcgyvr would refuse is scored as a failure here by its refusal code, and a cell
lost to a transport error is its own outcome rather than a model failure.

## Found

**The provenance marker was being sent to the worker.** `load_bundle` returned
the whole file, so `javascript.md`'s two-line UNMEASURED comment — 162 of 2039
bytes — opened the model's system prompt by telling it its own instructions were
an unmeasured port whose figures should not be cited, and was charged against
the ceiling `MAX_BUNDLE_BYTES` exists to enforce. Now stripped at load. The
marker stays in the file, which was the right half of #25's decision.

This is not only tidiness. **#144's two acceptance bullets are unsatisfiable
together while the marker is in the bytes:** a file cannot both keep an
UNMEASURED marker and end up byte-identical to the condition a sweep measured.
Stripping is what makes them compatible, and it had to be decided before a sweep
rather than after — whatever is in the artifact at run time is what was
measured.

**The worker prompt has no slot for the target file's current content.**
`worker_view()` exposes `task`, `target`, `interface`, `deps`,
`stop_conditions`, `output_schema` and `context.max_input_tokens`, and
`render_user_message` renders exactly those. So a `bug_fix` worker is asked to
return the whole new content of a file it was never shown. Nothing has hit this
because nothing dispatches yet (lane/25's "Left"). The 7 `bug_fix` and 2
`type_annotation` tasks carry their current content inside the `task` field,
which is the only slot available today; it is legal and it is what a decomposer
would have to do right now, but it makes those user messages a different shape
from what they will be once a slot exists. **Worth its own issue.**

**The Python task-set composition cannot be reproduced in mcgyvr's vocabulary.**
`data/task-catalog.json` has no `refactor` and no `edge_case` — they were never
in it, and the `excluded` list does not mention them, so this is absence rather
than rejection. The three refactor intents are `function_implementation` and the
two edge-case ones are `bug_fix`. A slice by type is 11/7/2 and a slice by
intent is 8/5/3/2/2; both are true and they are not comparable with the Python
per-category rates without saying which is meant. Pinned in a test so a task
added later has to state which arm it joins.

**Node 24 runs TypeScript directly**, so acceptance needs no compiler, no
install and no network — the isolation CLM-0004's design asks for, at no cost.
The price is that type *stripping* is not type *checking*: TypeScript erases, so
there is no analogue of the Python set's `typing.get_type_hints`, and t17/t18
assert the annotation form by reading their own source. That proves the
annotation is written, not that it is correct, and the README records it as a
threat to validity rather than a detail.

**Nothing reachable serves the model the experiment is defined on.** No GPU, no
local backend on any of the five probed ports. The Alibaba key is rejected,
Cerebras carries only large models, NVIDIA NIM has small coder models but no
Qwen. Substituting one would change the model and the serving stack at once —
under CAV-02 a figure from another backend describes different weights — so it
would answer a different question while looking like an answer to this one.
