# Session — lane/21 — 2026-08-03

## Did

Built #21: `src/mcgyvr/runner.py`, the first code below the seam #20 drew and the
first real consumer of `pool.Endpoint`. Two wire protocols, one interface.
`runner_for(endpoint)` is the only place a protocol selects an implementation and
`dispatch(source_map, rung, request)` is the only intended caller of `bind()`, so
a call site names a step of the ladder and never a machine. 47 tests; suite is
593 green, `ruff` and `mypy --strict` clean, baseline reports no blockers.

**The identity property is asserted as an equality, not a checklist.** One
`Request`, two backends, two different JSON documents saying the same thing —
and the only fields permitted to differ are the ones naming where it ran. That is
enforced structurally rather than by discipline: a protocol supplies a URL path,
a request body and a `_Parsed`, and the `Completion` is assembled once, in the
shared `generate()`. Neither path can come to mean something different by
"truncated" because neither path decides it.

**Truncation is read, never inferred, and `UNKNOWN` is not `complete`.** Only
`done_reason`/`finish_reason` are evidence. A word this runner does not know
(TGI's `eos_token` and the `max_tokens` some servers send *are* known) becomes
`StopReason.UNKNOWN`, with the backend's own word kept and a note saying the
answer is not being read as complete. The unoptimistic default is the point: text
that merely looks cut off is not truncation, and a backend that said nothing has
not said the answer is whole. Guessing from output shape is how a truncated file
gets applied as a whole one.

**The cap.** Required on every `Request` — no default and no sentinel, so an
uncapped dispatch is not expressible — and translated into each protocol's own
parameter. Nothing streams, so the honest description of "enforced" is: refuse to
issue an uncapped request, then check the backend's own reported count against
the ceiling it was sent. `overran_cap` is tri-valued and says which of *held*,
*overran* and *not checkable* happened; a `None` count is never read as 0,
because a zero averages into telemetry as a measurement of nothing.

**CAV-01 is honoured the way #21 words it — the dependency is allowed, the
silence is not.** Ollama's native `/api/generate` is implemented, because it is
what a default install offers and refusing it would refuse the common machine.
But `quality_safe=False` is a class attribute of that runner, so every completion
from it carries the flag and a note, and a `quality_sensitive` request raises
`QualityCaveatError` *before anything is sent*. The remedy named in the error is a
config edit rather than a code change: Ollama also serves the compatible shape, so
`api: openai` on the same host is the whole fix.

**ADR-0009 changed the design mid-build.** I had given `Request` a `stop` tuple
out of generic API instinct. ADR-0009 decides that v1 bounds a reply with the cap
and a named truncation and that **no stop sequences are sent** — and names #21 as
where #95's stop-token half folds in *with an empty set for `whole_file`*. So the
field is gone, and two tests hold the absence: one asserts neither protocol puts
`stop` on the wire, one asserts the field does not exist to fill in. A truncated
completion now also carries a note naming ADR-0009's rule, so the words travel
into telemetry rather than living only in a docstring. The reasoning that made
this worth removing rather than leaving harmlessly empty: a stop sequence is
consumed by the server and stripped, so under `whole_file` it converts a reply
that ran long into a shorter *valid* Python file the gate will pass — the failure
class turned from loud to silent, in a file.

**One accommodation with a reason.** `_url_for` drops a duplicate `/v1` when a
source's `base_url` already ends in one. The config reference documents
`base_url` as a root, which is right for the local backends, but every hosted
provider documents its endpoint *with* `/v1` — and pasting it would otherwise
produce `/v1/v1/chat/completions`, a 404 whose message points at the key or the
model rather than at the extra path segment. It lives in the runner rather than
the loader because appending a path is this module's business and `Endpoint` is
shared with callers that append nothing.

**#20's import guard was edited, deliberately.** `test_nothing_else_imports_the_endpoint_type`
forbade importing `Endpoint` anywhere but `pool.py`, and a runner is exactly what
the type was defined for. It is now `test_nothing_above_the_seam_imports_the_endpoint_type`
with a named `BELOW_THE_SEAM = {"pool.py", "runner.py"}`. Named rather than
pattern-matched on purpose: a third entry should be an argument someone makes,
not a file that quietly matched.

Transport is stdlib `urllib.request`, matching `detect.py` — no new dependency.
Failures are kept apart rather than folded together: `TransportError` (not
reached), `BackendError` (an HTTP status), `ProtocolError` (answered, unreadable),
`QualityCaveatError` (CAV-01). Most tests stub the transport and *record what was
sent*, since half these properties are about the request; two stand up a real
loopback `http.server`, so the keyless-local acceptance bullet is proven against
a socket — the server asserts it saw no `Authorization` header at all.
