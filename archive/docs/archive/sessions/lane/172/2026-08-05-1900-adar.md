does not say so.** One of five measurements is sound (ghostcall, 0/78), one is

commands of the form `python -c "from target import f"` write `__pycache__/`,
which tripped the gate's workspace-stable check before any assertion was judged.
The commit that landed the report, `8e24291`, states this plainly; REPORT.md was
committed already stale and never corrected. **No mcgyvr claim depends on any of
it** — `records/` cites only the 2026-08-02 `premise` path, which touches neither
the gate nor acceptance commands. Checked, not assumed.

**The tokens band is reported with the wrong sign.** REPORT.md gives median
−26.8% and recommends sizing the safety margin off a −89% negative tail.
Recomputed from the raw rows: **not one row under-estimates**. n=18 after the
chars-per-token guard, median +8.8%, max +22.5%. The negative tail it recommends
building on does not exist. The corrected figures are in the directory's own
`claims/tokens.json`, which its report contradicts.

**mcgyvr accepts a fenced refusal as file content.** Demonstrated against our own
parser, not inferred: `# I cannot complete this task.` and
`{"status":"blocked",...}` inside a fence both return `ParsedFile`, and both are
valid Python, so syntax and lint pass them. Only the *unfenced* refusal is caught,
by the existing ambiguity rule. Filed as #174. The second-order effect is the
expensive one — escalation fires on failure, so a refusal read as success means
the cascade never climbs.

**The prompt-fit reserve is multiplicative and the backend's overhead is not.**
`ESTIMATE_RESERVE = 0.32` on a 500-token prompt buys 160 tokens against an
overhead local-ai measured at 348. Under-covers small prompts, over-covers large
ones, and the error runs the dangerous way exactly where the reserve is smallest.
CLM-0011 never covered this term and `worker/prompt.py:57` already says why.
Filed as #173.

**One failure class survived every context condition and both model sizes.**
Re-derived inside this repository from evidence #118 vendored: t02 failed 8/8
cells — both models, 0.4 KB through 8 KB of bundle. The 30B was at ceiling
everywhere else. The failure is `input was mutated`, and the sibling cases are a
pinned annotation form and `bool` accepted as a number. All mechanically
checkable, none a judgment call. The sharp reading for #110: escalation cannot
fix this class, so a semantic check replaces the whole ladder rather than one
rung.

**Three local-ai defects share one shape** — acceptance commands silently never
running, `__pycache__` failing tasks before judgment, refusals passing as code.
Each produced a confident, specific, wrong number. Each was invisible until
someone read the mechanism instead of the number. The second happened while
fixing the first. That is the case for #167's positive control, and their
round-trip guard (the producer asserts the consumer received what it emitted)
is the transferable form.
