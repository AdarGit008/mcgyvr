`dependabot/**` family is declared (#91), both ecosystems are configured, all

`GET /dependabot/alerts` returns `403 — disabled for this repository`, so a CVE
in a pinned dependency would produce no signal at all. Version currency and
vulnerability disclosure are separate switches and only one of them is on.
Repo setting, not a tracked file.

**REC-01's three mutations are all one shape, and it is not the dangerous
one.** The warn reads as "records were edited after landing", which sounds like
history being rewritten. It is not: all three are additive or citation-fixing.
`cb3a4f1` appended four lines to CLM-0001 folding in vLLM measurements from the
predecessor repo; `8f35281` extended the reach corpus README as CLM-0008/0009
registered; `67c92db` (#118) replaced a CLM-0004 citation that pointed at a
moving branch with vendored evidence carrying a sha256. The last is the
strongest case that the rule as written is over-broad — the edit made the
record *more* durable, and the rule flagged it anyway. Worth deciding whether
REC-01 should distinguish "appended to" from "restated", because right now a
correction and a rewrite score the same and the warn cannot be cleared by good
behaviour.
