WHAT #276 CHANGED ABOUT #265. #265's scope said "one change to the comparability key, adding all three at once". #276 then decided that a field enters the key ONLY once perturbation shows it flips more verdicts than the declared bound, with recording explicitly unconditional and outside that rule. So the two acceptance items are not the same item: the encoding is #265's, the membership is #276's, and the three digests are RECORDED now and KEYED when admitted. The four bound-key fields — model, tier, bar, build — are exempt by #276 corollary 3, because the rule cannot hold `model` fixed while varying `model`.

THE DEFECT THAT REORDERED THE WORK. `require_comparable` compared `manifest.get(key)` across cells, so a key ABSENT FROM EVERY CELL yielded one value and passed. Demonstrated before writing anything: a fabricated `model_sha256` in the key changed no behaviour at all. Consequence — adding the three digests to the key today would have been a no-op that read, to every later reader, as having checked. So the shape and the refusal had to land together or neither was worth landing. This is also live and not hypothetical: `round` and `product_sha256` are carried by 6 of 139 manifests, so every pre-round table was passing a check it was not performing.

WHERE THE ABSENCE RULE HAD TO BE CUT. Making absence a refusal outright broke the ADR-0024 consequence that an endpoint which will not name its build records `null` and a rate from it is still a rate. The line that survives both: the defect is two records agreeing BY SHARED ABSENCE, and one record agrees with nothing. So a single record is never refused for what it could not answer, two records are, and `null` is a recorded fact about a run but never a match between two of them — an endpoint that would not answer twice may have answered differently twice. Half of ADR-0024's consequence stands, half is withdrawn, and the ADR says which.

WHAT LANDED. `tools/bench/identity.py` — the four groups, the three states (value / `null` + reason / absent key), one hashing convention, `require_comparable` with the absence refusal and an explicit `allow_unfingerprinted` waiver, `drift` for the resume checks, and `tag`/`inventory` for the migration. `report.py` now reads it, which retires three of the five disagreeing lists; the two runner drift checks are named in the fan-out and still carry their own. `--allow-unfingerprinted` on the report CLI, and the fields it could not check printed BESIDE THE NUMBERS rather than left in the shell history. 27 new tests, the per-field mutation case parametrised off the key itself so a field added without a mutation is a test failure.

THE MIGRATION IS COMPUTED, NOT STAMPED. Three tags over the 136 machine-written manifests: **verified 6, backfilled 126, no_fingerprint 4.** The 6 are the 7B bench runs of 2026-08-14, the only ones carrying a round pin. `verified` is against the key AS IT STANDS — which does not hold the three digests, because nothing writes them — so when the fan-out adds a writer those six demote on their own. That property is the whole reason the tag is computed on read: a stamped tag claims a fingerprint the run never carried. One rule needed cutting differently from `read_cell`'s: it requires `condition`, and 96 manifests are rig sweeps that never had one, so the tag does not inherit that requirement — "not a bench run" and "cannot say what produced it" are different states.

D9 IS DECLARED AND NOT ENFORCED, DELIBERATELY. `cells` joins `matching` in `reproducibility.json`, and the file now says so. The check was not written: what counts as "the paired set" at report time is #231's question, the test bound is 514 cells against cells of n=10 and n=100, and a strict equality rule would have dropped the bound from every table for a benefit that cannot be collected until #276's rule can run.
