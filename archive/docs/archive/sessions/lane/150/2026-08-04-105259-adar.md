Built #150: `target_content` on the contract schema, rendered as its own
section of the worker prompt, and moved 12 of #144's 20 contracts into it.

**The fork the issue asked to settle was already settled by the round-trip.**
Inlined on the contract, not read from the sandbox at prompt-build time.
Direct mode publishes the schema as public API, so an agent handing over a
contract should be handing over everything the worker will see; and
`parse(dumps(c))` round-tripping the actual bytes is what makes a recorded
contract re-runnable and a measurement quotable. Reading at dispatch would also
have put I/O inside `build_prompt`, which is pure.

**The section says what it is for, because a worker should not have to infer
it.** `CURRENT CONTENT OF solution.ts (this is the file to change):` — a model
shown a file and told to reply with "the complete new content of solution.ts"
is being asked to join two facts, and the join is free to state.

**The fence is chosen, not fixed.** `worker/reply.py` already parses under
CommonMark's rule that a fence closes only on one at least as wide; rendering
had to apply the same rule in the other direction, or a target containing a
fence (a docstring, a markdown template) would end its own block and hand the
worker a truncated file. No language tag: the header names the file, extension
included, and a tag inferred at render time would be a second statement of the
same fact with its own way of being wrong.

**Absence has one meaning and it is written down.** Empty = the target does not
exist yet, or its content is not needed. A `function_implementation` writing a
new file and one rewriting an existing file are the same contract shape; only
the presence of content separates them, so the loader cannot reject either.
What it *does* reject is content against a pattern target — there is no one
file it could be the content of, and a pattern target is deterministic-tier
work whose tools read files themselves.

**The fit check needed nothing.** `build_prompt` already charges
`system + "\n" + user` against `context.max_input_tokens`, so a target too
large to send is a preflight issue at the contract level. Tested rather than
assumed.
