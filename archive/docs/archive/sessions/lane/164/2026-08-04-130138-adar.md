The fix is that asking and dispatching stopped being one fact. PORT_CONVENTIONS now carries both, and for every backend but one they are the same answer. Ollama is the exception because each of its protocols is better at a different thing: native /api/tags is the only listing that enumerates models pulled but NOT loaded, which is exactly the inventory a proposal needs, while the OpenAI-compatible shape on the same port dispatches with identical model ids and no caveat. Asking natively and binding compatibly is not splitting the difference — it is each protocol used for what it is actually better at.

The design point that mattered: where the rule lives. My first cut put binds_as as a plain field defaulting to api, and a test fixture immediately fell through it — a Backend built by hand silently took the caveated default. Moved the rule into binds_as_for() reading the one convention table, so every construction path agrees and there is still a single source of truth. That was the fixture telling me the default was a trap, not that the fixture was wrong.
