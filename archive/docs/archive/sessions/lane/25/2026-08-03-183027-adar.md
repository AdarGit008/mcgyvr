## Found

**The JS adapter is named `js/ts`, not `javascript`.** The bundle registry keyed
on the adapter's own `name` was written against a guess and the tests caught it.
Worth noting because keying on the adapter name is the whole point — a second
table would not have failed, it would have silently diverged.

**One nesting case is not ambiguous, and the fence-width rule already handled
it.** A file containing fences, wrapped in a longer fence, is a single block
because a fence closes only on one at least as wide. This is *more permissive*
than the approved plan described (which said nested fences would be refused
outright), and it is not a guess being resolved — the widths decide. Equal-width
nesting still refuses. The tests and the module docstring record the real
behaviour rather than the plan's prediction of it.

**A defect ships deliberately.** c2's fifth output rule points at a section
headed OUT OF SCOPE that the measured runs' contract template carried and
mcgyvr's `worker_view()` has no equivalent of — `scope.forbid` is deliberately
not worker-facing under #94. The rule is inert here. The bundle ships verbatim
anyway, because editing it forfeits the measurement, and that costs more than
one vacuous line. It narrows how far the 70% figure transfers even for Python,
and saying so is cheaper than discovering it later.

**Two things are unmeasured about JS/TS, not one** (#144): whether a bundle
helps in that language at all, and whether 2 KB is the right ceiling for it. The
shipped file sits 27 bytes under a limit that is the peak of a Python curve.
