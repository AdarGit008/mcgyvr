# Session — lane/115 — 2026-08-03

## Did
Landed the deterministic half of ADR-0007: the symbol index now states what a
symbol looks like, so `deps[].signature` on a contract comes from the parser
rather than from the orchestrator model.

## Did

`Symbol` grew an optional `signature`, `SymbolKind` grew `IMPORT`, and both are
populated from the parse passes that already ran — no new module, no third
parse site, so ADR-0001 boundary 8 holds by construction.

Python signatures are `ast.unparse` of a shallow copy of the node the collector
already visits, body replaced by the docstring or by `...`. The copy is the
point: the tree the collector is still walking is untouched. Decorators are
kept — `@property` is interface. Normalising rather than slicing verbatim is
the one asymmetry with JS/TS, and it is forced: locating where a header ends in
text means locating the colon that terminates it, which annotations, lambdas
and multi-line parameter lists make a parsing problem in its own right.

JS/TS signatures are node text minus the body field — verbatim, so diffable.
One fragment is assembled rather than sliced: the `const` on an arrow binding,
because a declarator's own text begins at its name and a pure slice would lose
whether the binding is reassignable.

Imports record the name *depended upon*, not the one locally bound, since that
is the name the index holds a definition under; `detail` is the module, with
relative dots kept; the whole statement is on the signature, which is where an
alias survives. Star imports are recorded under `*` rather than dropped. A
re-export stays an export only — ADR-0007 already puts the barrel file in the
"the index cannot name this" bucket, and resolving it here would be the
fabrication the ADR exists to prevent.

## Found

Two consumers — the resolver's symbol maps and the read planner's anchors —
filtered on `is not SymbolKind.REFERENCE`. Adding a fourth kind would have
swept imports in as landing sites, so a file that merely imports `fetch` would
have ranked as a place to find it: the exact inversion the resolver exists to
avoid. Both now name the kinds they act on positively, so the next kind added
is a decision rather than a silent reclassification.

The cache encodes symbols as positional tuples, so the new field is a format
change; `CACHE_VERSION` is 2 and a version 1 cache is discarded rather than
served without signatures.

## Left

Whether the slice is *good* is not settled here and cannot be — a signature cut
from tree-sitter node text is only as correct as the grammar and the slicing
rule. ADR-0007 says as much: that is a parse defect, reproducible and coverable
by a test, and different in kind from a fabrication.

Python signature text is normalised by `ast.unparse`, so it is reproducible for
a given interpreter but not guaranteed identical across CPython versions. The
repo pins 3.12. If a contract's `deps` are ever diffed against an index built
on a different interpreter, that is where a spurious difference would come
from.
