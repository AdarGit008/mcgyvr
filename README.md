# mcgyvr

Offload scoped coding work from your agent to a configurable worker ladder.

mcgyvr runs one scoped coding task at a time. You author a *contract* — one
target, one task, one way to judge it — and mcgyvr executes it on a
deterministic tool or up a ladder of local and API models, keeps only what its
deterministic gate accepts, and leaves an accepted `code` change in your
working tree. It never commits unless told to, and it never writes anything
else into the repository. The contract vocabulary and the run workflow are
documented in `skills/mcgyvr/SKILL.md`; the config reference and that skill
are generated by `make docs` from the schemas in `src/mcgyvr/config.py` and
`src/mcgyvr/contract.py`.

## Entry points

The documented way in is `make`:

- `make setup` — install dependencies, frozen against `uv.lock`.
- `make test` — run the test suite (`pytest`).
- `make lint` — `ruff check .` and `ruff format --check .`.
- `make typecheck` — `mypy`, in strict mode.
- `make docs` — regenerate the config reference and the `/mcgyvr` skill.
- `make check` — everything CI runs: lint, typecheck, docs check, and test.

The CLI is `mcgyvr` (`mcgyvr.cli:main`, defined under `src/mcgyvr/cli/`).
`mcgyvr contract CONTRACT.yaml` validates a contract; `mcgyvr catalog` shows
the task vocabulary; `mcgyvr run CONTRACT.yaml --repo DIR` executes a contract;
`mcgyvr sessions` reads the chat/agent sessions the journal keeps. Read-only
introspection includes `mcgyvr config`, `mcgyvr local_pool`, `mcgyvr sandbox`,
and `mcgyvr capabilities`.

## Core concepts

- **Config schema** (`src/mcgyvr/config.py`) — a YAML setup declares `units`
  (address, model, engine, key variable name, limits), the ordered `ladder`
  work climbs cheapest-first, `sandbox` (mode, fallback, network), `delivery`,
  `verifier`, `orchestrator`, and the journal. Unknown, missing, or mis-typed
  keys are refused, and credentials are recorded as environment-variable
  names, never values.
- **Task catalog** (`data/task-catalog.json`) — the vocabulary of what mcgyvr
  can be asked to do: task types (`code`, `chat`, `agent`), the
  families work may start on (`deterministic`, `local`, `api`), and the
  evidence each type must carry.
- **Fleet** (`src/mcgyvr/fleet/`) — reads `fleet.yaml` (units, rigs, fleets)
  and `policy.yaml` (the ladder and policy settings), refusing keys that
  belong in another file or are unknown.
- **Gate** (`src/mcgyvr/gate/`) — the deterministic acceptance gate: scope and
  secret scans, per-language syntax and structural checks, lint and format
  rungs, typecheck, semantic resolution, and the contract's own acceptance
  commands, each attributed to the lines the worker added.
- **Ladder and worker model** — `src/mcgyvr/local_pool.py` resolves a config
  into the dispatch endpoints work may actually use; `src/mcgyvr/rig/` is the
  machine side that keeps a rig joined to its hub and reads and serves its
  hardware. A run climbs the ladder cheapest-first until a rung passes the
  gate or a ceiling stops it.
